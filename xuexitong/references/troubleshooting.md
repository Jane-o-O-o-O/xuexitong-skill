# 网络和写入异常

[技能入口](../SKILL.md) · [作业与附件](homework.md)

先使用当前任务已有日志、作业快照和结果文件。以下两个命令不联网，不需要登录，也不会读取 Cookie 值：

```text
python "SKILL_DIR/scripts/xuexitong.py" request-status
python "SKILL_DIR/scripts/xuexitong.py" network-info --target upload
```

`network-info` 的目标可选 `upload`、`course`、`login`。它按 Requests 实际选择方式显示代理主机、端口和是否配置认证，不输出代理账号、密码或完整地址。Windows 系统代理可能在没有 `HTTP_PROXY` 环境变量时仍然生效；未发现显式代理也不能排除 TUN/VPN。此命令不检查连通性、不修改代理，不能据此认定代理是故障原因。

## 读懂异常

网络错误保留原来的异常类型，同时提示操作阶段、目标主机与脱敏路径、耗时、超时预算和处理建议。不会输出查询参数、Cookie、请求正文、原始错误页面或代理凭据。耗时从本次请求通过本地限速检查后开始计算；读取超时可能发生在等待响应或接收数据期间，并不总是等待首个响应。

| `kind` | 含义与下一步 |
| --- | --- |
| `connect_timeout` | 连接没有及时建立；检查网络、DNS、代理及目标是否可达。连接阶段未完成记作 `not_sent`，仍不自动重试。 |
| `read_timeout` / `timeout` | 等待或读取响应超时；不能仅凭超时判定风控。写入可能生效，先回读。 |
| `proxy_error` | 代理连接异常；运行 `network-info` 检查当前有效配置，保留原设置供核对。 |
| `tls_error` | TLS 连接或证书校验异常；检查系统时间、证书与代理，保留证书校验。 |
| `connection_error` | 连接无法建立或中途断开；写请求结果保守地记作未确认。 |
| `http_error` | 已收到 HTTP 错误；413/415 检查文件大小/类型，5xx 可能是服务端或网关异常。 |
| `http_redirect` | 写请求收到重定向，未跟随跳转或再次发送正文；先核对登录、入口和远端结果。 |
| `interrupted` | 请求期间被取消；保留先前成功记录和当前未确认状态，退出码 130，不自动续传或重放。 |

验证码、HTTP 401/403、429 和本地请求预算继续走现有访问停止与冷却规则，记录在 `lastStop`，不作为普通超时处理。`lastNetworkError` 是历史记录，含时间、操作、`remoteOutcome` 等字段；后续恢复成功不会抹掉它，不能把这条历史记录当作当前仍有故障。

## 上传、暂存与提交分别核对

- 本地文件缺失、空文件、目录或页面缺少上传签名字段：在上传前停止，不用本机时间代替服务端签名时间。
- 附件上传成功：仅表示获得附件编号；仍需把 HTML 写入答案，再回读并交卷。指定 `upload --out` 可保留编号与 HTML；已有结果文件不会被覆盖。
- 上传超时、非 JSON、响应字段异常或文件信息不一致：保留文件与异常记录，不自动重传。答案为空只能证明附件没有写进答案，**不能证明之前的上传没有在文件服务中生效**。
- 暂存/交卷失败：结果文件的 `stage` 标明 `prepare`、`upload`、`save` 或 `submit`；`uncertain` 表示答案写入是否未确认，`attachmentUncertain` 单独表示上传是否未确认。
- 附件已成功上传但后续失败：结果中的 `uploadedAttachment` 保留 `objectId` 和 `html`。核对文件与目标题号后复用 HTML，无需重新上传。
- 远端成功但本地结果保存失败：提示会明确远端已接受的题号或输出附件记录；本地保存失败不撤销远端操作，先回读，勿重放。

对结果不确定的写操作，先 `verify` 回读；交卷后还需 `works --course COURSE_ID` 确认实际状态。不要把附件成功或暂存成功当成交卷成功。

若排查后仍需再次上传，明确选择原入口或列表提供的同一份电脑端入口，并使用新的结果文件保留本次尝试。电脑端入口是显式选项，不是超时后的自动备用路线。接口仍不可用时说明已确认的事实和未确定的原因；使用浏览器应符合用户当前偏好。
